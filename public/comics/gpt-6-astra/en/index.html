Meet GPT-6 AstraINTRODUCTION

GPT-6 Astra is OpenAI’s smartest model yet，在计算机操作（computer use）、网页浏览、软件工程、科学研究及专业工作方面拥有最先进水平的表现。它擅长跨代码、浏览器和专业软件执行多步骤工作流。

In multiple reviews, Astra usedSignificantly fewer output tokens Achieved stronger results - despite higher per-token pricing, the estimated API cost per task is lower than earlier models.

Astra is alsoThe strongest alignmentmodel: act cautiously, respect task boundaries, and communicate transparently. When instructions leave room for interpretation, it uses existing context to fill in conventional gaps on its own; and when the answer might change the outcome, it asks focused questions. It can incorporate new requirements, adjust direction as required, and answer side questions without losing the main mission.

Call it like this in a Responses API request:

model = "gpt-6-astra"

============ Chapter 3: Behavioral Characteristics ============
03

它的「性格」与调教总览PROMPTING BEST PRACTICES

Astra 比 GPT-5.6 Sol 等前代更聪明、更能干，同时也展现出一些Targeted optimization can be done through prompt的行为模式：

  • Initiative and follow-up —— 它被设计为更高效的协作者，因此当额外输入可能实质性改变结果时，More likely to stop and ask questions— and you might expect it to make reasonable assumptions on its own and stick to them.
  • instructions to follow ——The ability to follow universal instructions is stronger than ever, giving you greater control over your behavior. But it does not apply to skills and AGENTS.md 等文件中的指令也更敏感。强烈建议审计The skills the model has access to and the directives in the file that may affect its behavior.
  • Personality and style -- Tends to provide detailed, formatted responses and may reuse certain set phrases across sessions. Please clearly specify the writing style and structure required for your application.
  • subagent delegation — It may be delegated less frequently than your workflow requires. Please specify when and to what extent you use subagents to work in parallel.
  • 测试与验证 - When writing code, it tends to test thoroughly before deeming the task complete; for small tasks, this may lead to testing that goes beyond what the task requires.
============ Chapter 4: Five Training Spells ============
04

五条调教咒语（Prompt 原文 + 解读）PROMPT SPELLS

4.1 Initiative

★咒语一：让它更自主地干活 INITIATIVE & FOLLOW-THROUGH

Astra's ability to stay coherent during long missions is better than its predecessor, but it's also easier to ask for clarification where its predecessors would just assume. To make it more autonomous, start with this prompt:

PROMPT 
You should infer the user's intent and task scope from the instructions and prior conversation context. Your job is to bias towards action and carry the user's intended task to completion.

When the user expresses intent to perform new work or fix an existing issue, persist until the user's intended goal is complete. Progress autonomously towards the user's goal (e.g. creating isolated worktrees / checkouts if needed, resolving merge conflicts, read-only actions, creating draft PRs etc.) unless they are clearly destructive or irreversible.
Let the model learn from the contextInfer user intent and task scope, prefer action rather than inquiry, and complete the task along the way. As long as it is not an obviously destructive/irreversible operation (such as building a worktree, resolving conflicts, read-only operations, creating a draft PR), you should proceed independently.

当用户意图不清时，模型更可能要求澄清。若用户的措辞已隐含授权，用这条让它跟进执行：

PROMPT 
When the user's prompt indicates a request for action, such as "can you...", "I want to...", "help me..." and similar expressions, treat these as instructions to do the work and take action. Do not stop at acknowledging capability (e.g. "Yes…"), proposing a plan, or offering to continue. Do not settle for a partial or "helpful enough" solution that does not fully satisfy the user's task to save time, effort or tokens. If a task requires sustained work, complete all the necessary work until the intended outcome is fulfilled.
When users say "Can you..." "I want to..." "Help me...",直接当作执行指令——Don’t stop at “Okay,” don’t just give a plan, don’t ask “Do you want me to continue?” Don’t hand over a semi-finished product that is “almost enough” just to save time/tokens. You must work hard until the expected results are achieved.

Let the model only be in准备好具体、可评审的成果之后Request approval again to avoid being stuck before work starts:

PROMPT 
Before asking the user clarifying questions, you should complete the work that is already authorized from context and necessary to make the proposed action concrete and reviewable. The user should be approving a concrete, reviewable result. For example, before deploying a change, writing to an external application, merging a PR or publishing a site, do all the required work first so that user approval is the final step. You don't need user permission for reversible tasks, read-only actions, reviews or fixes, or anything for which authorization is provided earlier in the session or strongly implied from the task instruction.

Do not introduce unsolicited warnings, disclaimers, approval flows, or safety/compliance checklists due to hypothetical risk.
Before deploying, writing external applications, merging PRs, and publishing the website,先把所有能做的都做完，让用户批准成为最后一步。可逆操作、只读操作、评审修复等无需许可。也不要因假想风险而主动抛出警告、免责声明或审批流程。另外，模型默认喜欢边干活边问「非阻塞式」问题——按你应用需要的自主程度调整这些 prompt。

★Mantra 2: Clarify the priority of instructions INSTRUCTION FOLLOWING

Astra can follow longer instructions, but is also more sensitive to information in the context - for example, ambiguous or conflicting instructions in a skill file can cause it to pause prematurely and block work. pleaseExplicitly declare the priority of user instructions and skills：

PROMPT 
The user's instructions take precedence over guidelines provided in a skill. If explicit user instructions conflict with a skill's instructions, prioritize the user's instructions.
一句话定规矩：用户指令 > skill 指引。冲突时以用户为准。

When an application loads a large number of skills and AGENTS.md This type of instruction file allows the model to "provide" which skill and which instruction caused it to pause or turn, which can effectively improve the transparency of the behavior:

PROMPT 
If a skill causes you to ask for permission or confirmation, pause, leave requested work unfinished, or diverge from the user's intent, name and link to the exact SKILL.md file you read, quote the relevant instruction, and briefly explain how it applies. Distinguish explicit skill requirements from your interpretation of guidelines.
要求模型在因 skill 而暂停/要权限/偏离意图时，点名并链接具体的 SKILL.md 文件、引用相关指令原文、简要说明适用理由，并区分「skill 的明确要求」与「它自己的解读」。这条很适合用来排查隐藏的冲突指引。
4.3 Style of writing

★Mantra 3: Control its writing style PERSONALITY & WRITING STYLE

Astra 喜欢用列表、表格和 Markdown 让回复「便于扫读」。如果你的应用需要更少格式的连续段落，明确写出来：

PROMPT 
Default to using clear, concise paragraphs, each developing one main idea. Use lists only when the information is genuinely parallel, sequential, or easier to compare, and avoid nested lists unless the hierarchy cannot be expressed clearly in prose. Use plain, simple language: familiar words, concrete examples, and precise verbs. Prefer active voice and direct statements.

Make sure to state the main point clearly and early, then develop it with the explanation and detail the reader needs. Let each sentence build on what came before. Develop the points that matter and provide enough support to be useful.
Used by defaultclear and concise paragraphs（一段一个主旨）；只在信息真正并列/有序/需对比时才用列表；语言平实、主动语态；先亮观点Expand again, and each sentence continues the previous sentence.

技术沟通场景下，这条帮你在「清晰连贯」与「专业得体」之间取得平衡：

PROMPT 
Use plain language over jargon, and reference technical details only to the degree that it helps illustrate an idea or your work to the user. Communicate complex concepts in a clear and cohesive manner, and calibrate your writing to the level of background knowledge assumed from the user's prompt and context.
少堆术语，技术细节只在有助于说明时引用；并Calibrate based on user knowledge backgroundThe depth of writing.

想减少套话和「AI 腔」词汇，从这条开始：

PROMPT 
Avoid using slop words or phrases like "Bottom Line:" in conclusions, "delve," "foster," "leverage," "it's worth noting," "importantly," "Question? Answer." or "This isn't about X. It's about Y.", "genuinely" or hyphenated compound descriptions and adjectives. Do not use concluding summary statements such as "In short:..", "The simplest mental model is:...".

State the intended action directly. Avoid adding what you won't do, what will remain unchanged, or how you'll separate or categorize results. Do not use contrastive framing such as "X, not Y" or "X—not Y" that introduces an unprompted alternative that the user didn't ask about. Avoid invented compound labels like "exact-head checks" and "editorial-row layouts", vague qualifiers, and canned transitions; use plain verbs and prepositions to state the actual relationship directly.
An "AI cliché blacklist": disabled "delve""leverage""it's worth noting" Such general words,"In short:" 式总结、"Not X, but Y" 式对比框架、生造的复合标签和空洞过渡语。直接陈述要做的动作，用朴实的动词和介词说明真实关系。

★咒语四：调节子代理委派 SUBAGENT DELEGATION

Astra 接受过「拆分工作并委派给并行子代理」的训练。如果你的 harness 实现了多智能体系统，用这条调节委派力度：

PROMPT 
If at any point you can parallelize work by delegating tasks to another agent (no matter if you are the root or subagent), you should do so using collaboration tools if it could save time or improve quality.
无论模型是主代理还是子代理，只要能通过委派并行化、节省时间或提升质量，就应使用协作工具进行委派。模型对「何时、如何委派」的 prompt 响应良好，可据你的多智能体实现来调校。

Messages between brokers may contain syntax or spacing errors. This makes the messages between brokers more readable:

PROMPT 
Messages that you send to other agents and your final answer may be read by a human, so ensure they are legible. Always put proper spaces between words and/or numbers.
提醒模型：发给其他代理的消息和最终答案可能被人阅读，词与数字之间要正确留白，保证清晰易读。

★咒语五：校准测试强度 TESTING & VERIFICATION

写代码任务中，校准「一处改动需要多少测试与验证」，可避免为小改动做无谓的测试或重复检查：

PROMPT 
Do not write tests for reversible, low-impact changes that mirror the implementation. If you do choose to verify your work with tests, make sure that the tests are meaningful and necessary to verify implementation.

Run tests appropriate to the change and complete required checks. Once those pass, broaden or repeat testing only when new changes, failures, or unresolved concerns justify it; otherwise, continue toward completing the task.
可逆、低影响的改动不要写「复述实现」的测试;If you want to write, write something meaningful. First run the tests and necessary checks commensurate with the changes. After passing them, unless there are new changes, failures or unresolved issues, continue to advance the task and do not expand the scope of the test indefinitely.
============ Chapter 5: Migration ============
05

迁移速查表MIGRATION QUICKSTART

用 Codex 一键迁移

Codex 可以通过 OpenAI Docs skill 应用本指南中的推荐改动：

$openai-docs migrate this project to GPT-6 Astra

想在其他编程代理中使用该 skill，可从 OpenAI 的 skills 仓库下载。

手动迁移：把 model 设为 gpt-6-astra，然后逐项检查：

  • 推理强度：如果你现在用 none 或 minimal，先从 low 起步对比效果；否则保持当前有效推理强度。Responses 用 reasoning.effort, for Chat Completions reasoning_effort。
  • Tool call:使用 Responses API。Astra 虽支持 Chat Completions，但Tool calls must go through Responses。
  • Unsupported parameters:Remove temperature、top_p、top_logprobs；Chat Completions 还需移除 logprobs;Responses need to be obtained from include removed from message.output_text.logprobs。
  • Fast 模式：欧盟数据驻留请用 Standard 处理。Astra 在 EU 数据驻留下不支持 service_tier: "fast" or "priority"；且 Astra 的 Fast 模式不含延迟 SLA。
  • 变更推理强度：If the application needs to adjust the strength between replies, use it in a standard single-proxy request configuration_update Input; keep request level reasoning.effort 不变，以保留 prompt 前缀用于缓存。采用前先确认兼容性限制。
  • Prompt 缓存：从 GPT-5.5 或更早版本迁移时，把 prompt_cache_retention 替换为 prompt_cache_options.ttl and set to "30m"。注意查阅缓存边界与缓存写入计费等变更。
  • 不必要的审批停顿：如果模型总在推进前反复请求批准，用「咒语一」的主动性指引来提升自主执行程度。
💡 一句话总结： Astra is smarter and more "cautious" - if you want it to be fully powered, you must use prompt to tell it clearly:How much autonomy, who has the final say, how to write, when to delegate, how much to measure。
