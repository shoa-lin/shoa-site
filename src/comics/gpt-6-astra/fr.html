01

Faites connaissance avec GPT-6 AstraINTRODUCTION

GPT-6 Astra est le modèle le plus intelligent d'OpenAI à ce jour, avec des performances de pointe en utilisation d'ordinateur (computer use), navigation web, génie logiciel, recherche scientifique et travail professionnel. Il excelle dans les workflows en plusieurs étapes qui enchaînent code, navigateur et logiciels métier.

Sur de nombreux benchmarks, Astra obtient de meilleurs résultats avec nettement moins de tokens en sortie — malgré un prix au token plus élevé, le coût API estimé par tâche est donc inférieur à celui des modèles précédents.

Astra est aussi le modèle le mieux aligné : prudent dans ses actions, respectueux du périmètre de la tâche, transparent dans sa communication. Quand les instructions laissent place à l'interprétation, il comble lui-même les lacunes courantes grâce au contexte disponible ; quand la réponse pourrait changer le résultat, il pose une question ciblée. Il sait intégrer de nouvelles exigences, changer de cap à la demande et répondre aux questions annexes sans perdre de vue la tâche principale.

Pour l'appeler dans une requête Responses API :

model = "gpt-6-astra"
02

Quoi de neuf ?WHAT'S NEW

Nouveauté
ASYNC TOOL CALLING

Appel d'outils asynchrone

Pendant que votre application exécute un outil, Astra peut continuer à raisonner, appeler d'autres outils ou répondre d'abord aux parties indépendantes de la requête. Définissez async: true sur un function / custom tool, puis renvoyez le résultat avec le call_id d'origine quand il est prêt. L'exécution des outils et le travail en attente restent gérés par votre application.

Nouveauté
MID-TURN STEERING

Changer de cap en plein tour

Pendant que le modèle travaille, vous pouvez ajouter de nouvelles instructions utilisateur — une correction ou un changement d'exigence, par exemple. Via une connexion WebSocket, la Responses API conserve le travail déjà accompli et intègre la mise à jour dans la suite de la génération.

Nouveauté
CONFIGURATION UPDATE

Changer l'effort de raisonnement en cours de session

Ajoutez un élément d'entrée configuration_update pour augmenter le reasoning effort sur les tâches difficiles et le baisser pour les questions de suivi courantes — sans réécrire le préfixe du prompt d'origine, le cache est donc préservé. Le réglage reste actif jusqu'au prochain configuration_update.

Sécurité
MISALIGNMENT MONITORING

Surveillance du désalignement

Dans le cadre des mesures de sécurité renforcées d'Astra, les systèmes d'OpenAI surveillent de façon asynchrone les comportements de désalignement (misalignment) et déclenchent des alertes si nécessaire.

Attention
LIMITATIONS

Limites

Astra ne prend pas en charge l'effort de raisonnement none ; le mode Fast n'est pas disponible avec la résidence des données dans l'UE (EU data residency).

Hérité
GPT-5.6 CAPABILITIES

Toutes les capacités existantes conservées

computer use, Structured Outputs, streaming, Programmatic Tool Calling, orchestration multi-agents, cache de prompt, raisonnement persistant, compaction, mode pro — tout ce que GPT-5.6 savait faire, Astra le prend en charge.

03

Son « caractère » et comment le réglerPROMPTING BEST PRACTICES

Astra est plus intelligent et plus capable que ses prédécesseurs comme GPT-5.6 Sol, mais il montre aussi quelques comportements qu'on peut ajuster finement par le prompt :

  • Initiative et suivi — Conçu comme un collaborateur plus efficace, il a davantage tendance à s'arrêter pour poser une question quand une information supplémentaire pourrait changer le résultat de façon significative — là où vous attendriez peut-être qu'il fasse une hypothèse raisonnable et poursuive.
  • Respect des instructions — Il suit les instructions générales mieux que jamais, ce qui vous donne plus de contrôle sur son comportement. Mais il est aussi plus sensible aux instructions contenues dans les skills et dans des fichiers comme AGENTS.md. Il est fortement recommandé d'auditer les skills et fichiers accessibles au modèle pour y repérer les instructions susceptibles d'influencer son comportement.
  • Personnalité et style d'écriture — Il penche vers des réponses détaillées et très mises en forme, et peut réutiliser certaines tournures d'une session à l'autre. Précisez explicitement le style et la structure dont votre application a besoin.
  • Délégation aux sous-agents — Il délègue peut-être moins souvent que votre workflow ne l'exige. Indiquez quand et dans quelle mesure utiliser des subagents pour paralléliser le travail.
  • Tests et vérification — Quand il écrit du code, il a tendance à tester à fond avant de considérer la tâche terminée ; sur une petite tâche, cela peut déborder du périmètre nécessaire.
04

Cinq formules magiques (prompt original + explication)PROMPT SPELLS

★Formule n° 1 : le rendre plus autonome INITIATIVE & FOLLOW-THROUGH

Astra tient la distance sur les longues tâches mieux que ses prédécesseurs, mais il demande aussi plus volontiers une clarification là où « l'ancienne génération aurait tranché toute seule ». Pour le rendre plus autonome, commencez par ce prompt :

PROMPT 
You should infer the user's intent and task scope from the instructions and prior conversation context. Your job is to bias towards action and carry the user's intended task to completion.

When the user expresses intent to perform new work or fix an existing issue, persist until the user's intended goal is complete. Progress autonomously towards the user's goal (e.g. creating isolated worktrees / checkouts if needed, resolving merge conflicts, read-only actions, creating draft PRs etc.) unless they are clearly destructive or irreversible.
On demande au modèle de déduire l'intention de l'utilisateur et le périmètre de la tâche à partir du contexte, de privilégier l'action plutôt que la question, et d'aller jusqu'au bout. Tant que l'opération n'est pas clairement destructrice ou irréversible (créer un worktree, résoudre un conflit, actions en lecture seule, ouvrir une PR brouillon), il doit avancer de lui-même.

Quand l'intention de l'utilisateur est floue, le modèle a plus de chances de demander une clarification. Si la formulation de l'utilisateur vaut déjà autorisation, cette consigne le pousse à enchaîner :

PROMPT 
When the user's prompt indicates a request for action, such as "can you...", "I want to...", "help me..." and similar expressions, treat these as instructions to do the work and take action. Do not stop at acknowledging capability (e.g. "Yes…"), proposing a plan, or offering to continue. Do not settle for a partial or "helpful enough" solution that does not fully satisfy the user's task to save time, effort or tokens. If a task requires sustained work, complete all the necessary work until the intended outcome is fulfilled.
Quand l'utilisateur dit « tu peux… », « je veux… », « aide-moi à… », on traite ça comme un ordre d'exécution — pas question de s'arrêter à « oui, c'est possible », de livrer seulement un plan ou de demander « je continue ? ». Pas question non plus de rendre un travail « à peu près suffisant » pour économiser du temps ou des tokens : il faut aller jusqu'au résultat attendu.

Pour que le modèle ne demande d'approbation qu'une fois un résultat concret et vérifiable prêt, au lieu de se bloquer avant même de commencer :

PROMPT 
Before asking the user clarifying questions, you should complete the work that is already authorized from context and necessary to make the proposed action concrete and reviewable. The user should be approving a concrete, reviewable result. For example, before deploying a change, writing to an external application, merging a PR or publishing a site, do all the required work first so that user approval is the final step. You don't need user permission for reversible tasks, read-only actions, reviews or fixes, or anything for which authorization is provided earlier in the session or strongly implied from the task instruction.

Do not introduce unsolicited warnings, disclaimers, approval flows, or safety/compliance checklists due to hypothetical risk.
Avant de déployer, d'écrire dans une application externe, de fusionner une PR ou de publier un site, on fait d'abord tout ce qui peut l'être, pour que l'approbation de l'utilisateur soit la toute dernière étape. Opérations réversibles, lecture seule, revues et correctifs : pas besoin de permission. Et pas d'avertissements, de clauses de non-responsabilité ni de flux d'approbation ajoutés pour un risque hypothétique. À noter : par défaut, le modèle aime poser des questions « non bloquantes » tout en travaillant — ajustez ces prompts selon le degré d'autonomie que votre application attend.

★Formule n° 2 : fixer la priorité des instructions INSTRUCTION FOLLOWING

Astra suit des instructions plus longues, mais il est aussi plus sensible aux informations présentes dans le contexte — une consigne vague ou contradictoire dans un fichier de skill peut le faire s'arrêter trop tôt et bloquer le travail. Déclarez explicitement la priorité entre instructions utilisateur et skills :

PROMPT 
The user's instructions take precedence over guidelines provided in a skill. If explicit user instructions conflict with a skill's instructions, prioritize the user's instructions.
Une règle en une phrase : instructions utilisateur > consignes des skills. En cas de conflit, l'utilisateur a le dernier mot.

Quand l'application charge beaucoup de skills et de fichiers d'instructions du type AGENTS.md, demander au modèle de « dénoncer » le skill et l'instruction précise qui l'ont fait s'arrêter ou dévier améliore nettement la transparence :

PROMPT 
If a skill causes you to ask for permission or confirmation, pause, leave requested work unfinished, or diverge from the user's intent, name and link to the exact SKILL.md file you read, quote the relevant instruction, and briefly explain how it applies. Distinguish explicit skill requirements from your interpretation of guidelines.
Quand un skill le pousse à s'arrêter, à demander une permission ou à s'écarter de l'intention, le modèle doit nommer et lier le fichier SKILL.md exact, citer l'instruction concernée, expliquer brièvement pourquoi elle s'applique, et distinguer « ce que le skill exige explicitement » de « sa propre interprétation ». Très pratique pour débusquer des consignes contradictoires cachées.

★Formule n° 3 : tenir son style en laisse PERSONALITY & WRITING STYLE

Astra adore les listes, les tableaux et le Markdown pour rendre ses réponses « faciles à parcourir ». Si votre application préfère des paragraphes continus avec moins de mise en forme, dites-le noir sur blanc :

PROMPT 
Default to using clear, concise paragraphs, each developing one main idea. Use lists only when the information is genuinely parallel, sequential, or easier to compare, and avoid nested lists unless the hierarchy cannot be expressed clearly in prose. Use plain, simple language: familiar words, concrete examples, and precise verbs. Prefer active voice and direct statements.

Make sure to state the main point clearly and early, then develop it with the explanation and detail the reader needs. Let each sentence build on what came before. Develop the points that matter and provide enough support to be useful.
Par défaut, des paragraphes clairs et concis (une idée par paragraphe) ; des listes uniquement quand l'information est vraiment parallèle, séquentielle ou à comparer ; un langage simple, à la voix active ; l'idée principale d'abord, puis le développement, chaque phrase s'appuyant sur la précédente.

En communication technique, cette consigne aide à trouver l'équilibre entre « clair et cohérent » et « professionnel et bien calibré » :

PROMPT 
Use plain language over jargon, and reference technical details only to the degree that it helps illustrate an idea or your work to the user. Communicate complex concepts in a clear and cohesive manner, and calibrate your writing to the level of background knowledge assumed from the user's prompt and context.
Moins de jargon ; les détails techniques seulement quand ils éclairent le propos ; et une profondeur d'écriture calibrée sur les connaissances de l'utilisateur.

Pour réduire les formules toutes faites et le vocabulaire « qui sent l'IA », commencez ici :

PROMPT 
Avoid using slop words or phrases like "Bottom Line:" in conclusions, "delve," "foster," "leverage," "it's worth noting," "importantly," "Question? Answer." or "This isn't about X. It's about Y.", "genuinely" or hyphenated compound descriptions and adjectives. Do not use concluding summary statements such as "In short:..", "The simplest mental model is:...".

State the intended action directly. Avoid adding what you won't do, what will remain unchanged, or how you'll separate or categorize results. Do not use contrastive framing such as "X, not Y" or "X—not Y" that introduces an unprompted alternative that the user didn't ask about. Avoid invented compound labels like "exact-head checks" and "editorial-row layouts", vague qualifiers, and canned transitions; use plain verbs and prepositions to state the actual relationship directly.
Une « liste noire des tics de l'IA » : interdits les mots galvaudés comme "delve", "leverage", "it's worth noting", les conclusions façon "In short:", les oppositions du type « ce n'est pas X, c'est Y », les étiquettes composées inventées et les transitions creuses. On énonce directement l'action à mener, avec des verbes et des prépositions simples qui disent la vraie relation entre les choses.

★Formule n° 4 : doser la délégation aux sous-agents SUBAGENT DELEGATION

Astra a été entraîné à « découper le travail et le déléguer à des sous-agents en parallèle ». Si votre harnais d'exécution implémente un système multi-agents, utilisez cette consigne pour régler l'intensité de la délégation :

PROMPT 
If at any point you can parallelize work by delegating tasks to another agent (no matter if you are the root or subagent), you should do so using collaboration tools if it could save time or improve quality.
Que le modèle soit agent racine ou sous-agent, dès qu'une délégation permet de paralléliser, de gagner du temps ou d'améliorer la qualité, il doit passer par les outils de collaboration. Le modèle réagit bien aux prompts sur « quand et comment déléguer » : ajustez-les à votre implémentation multi-agents.

Les messages entre agents peuvent contenir des fautes de grammaire ou d'espacement ; cette consigne les rend plus lisibles :

PROMPT 
Messages that you send to other agents and your final answer may be read by a human, so ensure they are legible. Always put proper spaces between words and/or numbers.
On rappelle au modèle que les messages envoyés aux autres agents et sa réponse finale peuvent être lus par un humain : des espaces corrects entre les mots et les nombres, pour que tout reste clair et lisible.

★Formule n° 5 : calibrer l'intensité des tests TESTING & VERIFICATION

Sur les tâches de code, calibrer « combien de tests et de vérifications mérite une modification » évite les tests inutiles ou les vérifications répétées pour un petit changement :

PROMPT 
Do not write tests for reversible, low-impact changes that mirror the implementation. If you do choose to verify your work with tests, make sure that the tests are meaningful and necessary to verify implementation.

Run tests appropriate to the change and complete required checks. Once those pass, broaden or repeat testing only when new changes, failures, or unresolved concerns justify it; otherwise, continue toward completing the task.
Pas de tests qui « récitent l'implémentation » pour des changements réversibles et à faible impact ; si on en écrit, qu'ils aient du sens. On lance d'abord les tests proportionnés au changement et les vérifications obligatoires ; une fois au vert, on poursuit la tâche sauf nouveau changement, échec ou doute non résolu — sans élargir les tests à l'infini.

Aide-mémoire de migrationMIGRATION QUICKSTART

Migrer en un clic avec Codex

Codex peut appliquer les changements recommandés dans ce guide via le skill OpenAI Docs :

$openai-docs migrate this project to GPT-6 Astra

Pour utiliser ce skill dans un autre agent de programmation, téléchargez-le depuis le dépôt de skills d'OpenAI.

Migration manuelle : réglez model sur gpt-6-astra, puis passez en revue point par point :

  • Effort de raisonnement : si vous utilisez aujourd'hui none ou minimal, commencez par low et comparez les résultats ; sinon, gardez l'effort de raisonnement qui fonctionne actuellement. Responses utilise reasoning.effort, Chat Completions reasoning_effort.
  • Appel d'outils : utilisez la Responses API. Astra prend en charge Chat Completions, mais l'appel d'outils doit passer par Responses.
  • Paramètres non pris en charge : retirez temperature, top_p, top_logprobs ; avec Chat Completions, retirez aussi logprobs ; avec Responses, retirez message.output_text.logprobs de include.
  • Mode Fast : avec la résidence des données dans l'UE, utilisez le traitement Standard. Astra ne prend pas en charge service_tier: "fast" ni "priority" en résidence des données UE ; et le mode Fast d'Astra n'inclut pas de SLA de latence.
  • Changer l'effort de raisonnement : si l'application doit ajuster l'effort entre deux réponses, utilisez l'élément d'entrée configuration_update dans une requête mono-agent standard ; laissez reasoning.effort inchangé au niveau de la requête pour préserver le préfixe du prompt et le cache. Vérifiez les limites de compatibilité avant de l'adopter.
  • Cache de prompt : en migrant depuis GPT-5.5 ou une version antérieure, remplacez prompt_cache_retention par prompt_cache_options.ttl réglé sur "30m". Consultez aussi les changements concernant les frontières de cache et la facturation des écritures en cache.
  • Pauses d'approbation inutiles : si le modèle demande sans cesse une validation avant d'avancer, utilisez les consignes d'initiative de la « formule n° 1 » pour renforcer son autonomie.
💡 En une phrase : Astra est plus intelligent, mais aussi plus « prudent » — pour le faire tourner à plein régime, dites-lui clairement dans le prompt : quelle autonomie, qui décide, comment écrire, quand déléguer, combien tester.
